Frequently Asked Questions

Browse through quick answers to common questions about using Portly.

How does Portly find listening ports?
Portly inspects active network sockets (both TCP and UDP) on your local macOS machine using lightweight system queries, linking each socket back to its active Parent Process ID (PID) and command line arguments.
Does Portly support Docker containers?
Yes! Portly detects when Docker Desktop is running and connects to the local Docker Unix socket. It resolves port mappings automatically, displaying the actual Docker container names in the menu bar panel.
Why are macOS system processes hidden?
By default, system processes (like ControlCenter or rapportd) are hidden to keep your list clean and focused on your active development servers. You can show them at any time by toggling "Show macOS System Processes" from the settings gear menu.
Can I terminate processes directly from Portly?
Yes. Hovering over a row displays a "Stop" button. Clicking this button sends a standard SIGTERM signal to terminate the local process listening on that port, saving you a trip to the Terminal.
How can I launch Portly automatically on startup?
You can enable "Launch at Login" from the settings gear menu inside the Portly panel to configure the application to launch automatically when you sign into your macOS account.
